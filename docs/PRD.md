# 產品需求文件 (PRD)：課外活動報名系統

## 1. 專案概述
- **背景與動機**：目前大學生課外活動報名常散落於各處（如 Google 表單、社群粉專等），缺乏統一管理與追蹤機制。為了提升活動籌備效率與學生報名體驗，預計建立一個可以統一管理課外活動報名的系統。
- **目標用戶**：大學生（包含一般學生參與者，以及社團/學生會等主辦方管理者）。
- **核心價值主張**：提供一個直覺且單一的平台，讓主辦方輕鬆建立活動與管理名單，並讓參與者快速瀏覽、報名有興趣的活動。

## 2. 功能需求
以下為系統主要功能及對應的使用者故事：

1. **建立活動**
   - 作為 **系統管理者/主辦方**，我希望 **能夠在系統中新增、編輯或刪除活動資訊（包含名稱、時間、地點、簡介、人數上限等）**，以便 **提供學生最新且正確的活動資訊**。
2. **顯示報名人數**
   - 作為 **參與學生**，我希望 **能夠在活動頁面上清楚看到目前的報名人數與名額上限**，以便 **快速評估自己是否還有機會參與**。
3. **額滿自動關閉報名按鈕**
   - 作為 **系統管理者/主辦方**，我希望 **當報名人數達到設定的上限時，系統能自動隱藏或停用報名按鈕**，以便 **防止超額報名，減少後續人工協調的困擾**。
4. **管理者後台**
   - 作為 **系統管理者/主辦方**，我希望 **有一個專屬且需登入的後台管理介面**，以便 **總覽所有活動狀態、檢視個別報名名單與進行系統管理**。
5. **收集報名者基本資料**
   - 作為 **系統管理者/主辦方**，我希望 **在學生點擊報名時，能填寫並收集基本資料（如姓名、學號、聯絡方式等）**，以便 **作為活動報到核對及行前通知的依據**。

## 3. 非功能需求
- **技術限制**：系統將採用 Python Flask 框架作為後端，搭配 Jinja2 模板引擎進行前端渲染，資料庫則使用 SQLite。
- **效能考量**：系統需能承受熱門活動開放報名時的瞬間流量，頁面載入及操作回應時間應低於 3 秒。
- **安全考量**：
  - 管理者後台需有身分驗證（登入機制）與權限控管。
  - 使用者資料需妥善儲存，表單送出應具備基本的資料驗證，以防範常見的安全漏洞（如 SQL Injection、XSS）。

## 4. MVP 範圍 (Minimum Viable Product)
- **Must Have (必須有)**：
  - 建立/編輯/刪除活動功能。
  - 前台活動列表與內頁展示。
  - 學生報名功能與基本資料收集。
  - 額滿自動關閉報名功能。
  - 基本的管理者後台（能看到活動與報名者名單）。
- **Should Have (應該有)**：
  - 顯示各活動目前的報名人數與上限。
  - 管理者登入機制。
- **Nice to Have (可以有)**：
  - 報名名單匯出功能（如 Excel 或 CSV）。
  - 活動分類標籤或搜尋過濾器。
  - 寄送報名成功確認信件。
